# Deploying the MCP server

The server runs on Cloud Run in `gym-tracker-44a5f` (ADR 0001), in
`us-central1`, next to the Firestore database (`nam5`). The image is built and
deployed by `.github/workflows/mcp-deploy.yml`, because Cloud Run is amd64
only and `dart build cli` cannot cross-compile. Nothing is deployed from a
workstation and no service-account key exists for it: GitHub Actions signs in
through Workload Identity Federation.

Until OAuth lands (D5) the server accepts one personal token, mapped to one uid.

## One-time setup

The project's cloud resources are OpenTofu in Martin's system repository,
`infra/gym_tracker/mcp.tf`: the APIs, the Artifact Registry repository, the
runtime service account (read-only until D6: it bypasses `firestore.rules`),
the deployer service account and the Workload Identity pool it is reached
through, the two secrets with the token generated by tofu, and a 5-unit budget
with alerts at 50, 90 and 100 %. Cloud Run needs the Blaze plan first.

After the apply, put the values of `tofu output github_actions_variables` into
the repository's Actions **variables** (not secrets): Settings → Secrets and
variables → Actions → Variables. `tofu output -raw mcp_personal_token` is the
token for the clients.

### Cost caps

`max-instances=1` bounds compute, and the server's request budget (60 a minute,
1000 a day per token, checked before any Google call) bounds Firestore reads.
The budget only alerts. Disabling billing when it is exceeded takes a Pub/Sub
topic and a function, as in [Disable billing usage with
notifications](https://cloud.google.com/billing/docs/how-to/disable-billing-with-notifications);
budget data lags by hours, so that caps a runaway, not a spike.

## Deploying

Actions → MCP deploy → Run workflow, on `main`, or from any checkout:

```bash
gh workflow run mcp-deploy.yml --ref main
```

It refuses a commit whose `ci.yml` push run did not pass. The run summary
shows the URL: `https://gym-tracker-mcp-<number>.us-central1.run.app/mcp`.

## Checking it

```bash
MCP_TOKEN=<token> dev-run just mcp-smoke https://gym-tracker-mcp-<number>.us-central1.run.app/mcp
```

lists the five tools and your routines. Then connect a client:

```bash
claude mcp add --transport http gym https://gym-tracker-mcp-<number>.us-central1.run.app/mcp \
  --header "Authorization: Bearer <token>"
```

On claude.ai a custom connector works only if its dialog shows the Request
headers section: No sign-in, `Authorization: Bearer <token>`. ChatGPT has no
header option and waits for OAuth.
